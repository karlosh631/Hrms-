## 3. Node.js creator ditches Deno to work on open source Cloudflare Workers

### Overview
Cloudflare has acquired Deno, the startup founded by Node.js creator Ryan Dahl.
The deal is structured as an acquihire of Dahl and twelve of his engineering colleagues.
Deno's runtime development will be wound down after a one-year maintenance window.
Dahl is turning his efforts toward evolving Cloudflare's Workers platform.
He now argues that choosing Node.js to build servers is the wrong approach.
His team aims to make Workers technology available for standalone, open-source deployment.
This marks a major pivot in Dahl's ongoing quest to reshape server-side computing.

### What happened
Cloudflare officially announced the acquisition of Deno last week.
Dahl founded Deno to serve as an alternative to his earlier creation, Node.js.
Under the deal, Deno has no ongoing long-term future at Cloudflare.
Cloudflare committed to providing bug fixes and security patches for only one more year.
Dahl is now looking for an external home to adopt the MIT-licensed Deno project.
He suggested the OpenJS Foundation could become Deno's new home.
Twelve Deno team members are joining Cloudflare alongside Dahl.
Dahl's recently released project called celld is also being discontinued.
Dahl and his team will now focus entirely on Cloudflare's runtime infrastructure.

### Why it matters
Dahl originally introduced Node.js in 2009 to solve Apache's high memory consumption.
Node.js allowed JavaScript to run concurrently on servers using Google's V8 engine.
It could handle thousands of requests per second using minimal memory compared to Apache.
Node.js became a foundational web technology powering roughly 30 million websites today.
The platform has accumulated over 130 million downloads for external and internal operations.
In 2018, Dahl unveiled Deno as an anagram rewrite to fix Node's architectural flaws.
Deno featured native TypeScript support, built-in fetch, and a strict security permission model.
Venture firm Sequoia backed Dahl's startup with $21 million in 2022.
Deno managed to reach 400,000 monthly active users by August.
Despite that growth, Deno could not escape the immense gravitational pull of Node.js.
Dahl noted that developers could not easily deviate from established Node.js patterns.
Deno had to backpedal on original promises to ensure backward compatibility with Node.js.
Dahl acknowledged that Deno ultimately became merely an alternative implementation of Node.js.

### Technical details
Dahl noted that conventional servers operate at the Linux virtual machine layer.
Cloudflare Workers bypass virtual machines entirely by utilizing Google V8 isolates.
V8 isolates operate as lightweight sandboxes running inside a single operating system process.
This architecture removes the requirement for a dedicated application runtime environment.
Durable Objects was created by engineer Kenton Varda to enable stateful edge computing.
It allows developers to build stateful, real-time distributed systems at the network edge.
Durable Objects spin up instances dynamically at edge locations nearest to users.
Each instance operates as a single-threaded micro-server assigned a unique global ID.
User session data is stored locally in each instance using a dedicated copy of SQLite.
Dahl described Durable Objects as the perfect abstraction for modern distributed systems.
In August, Dahl launched celld as an open-source implementation of Durable Objects.
His goal with celld was to enable Durable Objects to run anywhere outside Cloudflare.
Cloudflare had previously open-sourced workerd in 2022 primarily for developer testing.
However, workerd was never made fully self-hosting or capable of managing distributed state.
Dahl's new mission is to merge celld and workerd into a standalone JavaScript runtime.
The combined runtime will support both JavaScript and WebAssembly workloads.
The resulting isolate-based runtime requires only 300 KB of memory per instance.
Standard Node.js and Deno instances typically require hundreds of megabytes of memory.

Background:
- Node.js is an open-source server runtime based on Google's V8 JavaScript engine.
- Cloudflare Workers is a serverless computing platform operating on distributed edge infrastructure.
- Workerd is an open-source runtime created by Cloudflare to run Workers code locally.
- Kenton Varda is the Cloudflare engineer credited with the design of Durable Objects.
- It is not yet known which specific foundation or organization will accept the Deno project.
- It is not yet known when Dahl's merged standalone workerd runtime will be released.
- The precise financial terms of Cloudflare's acquisition of Deno have not been disclosed.

### Industry impact
A runtime requiring only 300 KB per instance creates massive cloud infrastructure savings.
These memory efficiencies are particularly valuable for resource-heavy AI agent workloads.
The independent server-side JavaScript runtime market is undergoing rapid consolidation.
Deno is effectively exiting active commercial development under Cloudflare ownership.

## 4. Big Fish: Exploiting a 37-Year-Old Kernel Bug in OpenBSD

### Overview

Security research firm Calif detailed an exploit against a decades-old vulnerability in OpenBSD.

The primary flaw traces back approximately 37 years to the original BSD source code.

The issue stemmed from defining a shared memory attachment counter as a signed 16-bit short.

Attackers chained this counter overflow with a separate out-of-bounds kernel write.

The combined exploit chain allowed local privilege escalation directly to root.

Exploitation succeeded despite kernel mitigations including KARL, SMAP, and SMEP being enabled.

The attack chain did not require any information disclosure vulnerability.

OpenBSD patched the underlying flaws in errata 018 and errata 026.

Calif also outlined several hardening measures to systematically eliminate these exploit paths.

### What happened

Calif reported vulnerabilities along with suggested patches to OpenBSD earlier this year.

The root vulnerability resided in the shared memory attachment counter named shm_nattch.

The counter was stored in the kernel using a 16-bit signed short integer.

Repeatedly forking a process with shared memory records pushed the counter past 32,767.

Crossing 32,767 caused the signed counter value to wrap into negative numbers.

This integer overflow created a race condition resulting in a use-after-free state.

Researchers coupled the use-after-free with an out-of-bounds write inside the kernel.

The resulting multi-stage attack escalated a local user to root privileges.

OpenBSD addressed the issues in errata 026 and errata 018.

### Why it matters

Vulnerabilities written nearly four decades ago can persist unnoticed in modern operating systems.

The exploit demonstrated how deterministic memory allocators undermine protections like KARL.

OpenBSD is widely known for championing proactive system hardening and security features.

Existing hardware defenses like SMAP and SMEP were bypassed without an information leak.

Deterministic allocations allow attackers to predict function pointer addresses across system reboots.

Raising attacker cost requires proactively neutralizing entire classes of memory safety bugs.

Defensive investments are increasingly critical in an era of AI-assisted vulnerability discovery.

Proactive mitigations reduce the feasibility of weaponizing low-level kernel corruption bugs.

### Technical details

The exploit achieved code execution using a write-what-where primitive.

The memory write was triggered through kernel execution of TAILQ_REMOVE.

The what was a userland memory mapping configured to be accessible in supervisor mode.

Making this userland mapping supervisor-accessible allowed the exploit to bypass SMAP and SMEP.

The where target was a predictable kernel pointer location across reboots.

OpenBSD's KARL relinks the kernel binary to randomize function and data addresses.

However, OpenBSD's kernel memory allocators remain entirely deterministic.

Both the boot-time allocator and the best-fit allocator lack base address randomization.

Early boot allocations consistently land at identical locations across boots on the same hardware.

Structure allocations containing function pointers become reliable targets for memory corruption.

The exploit reliably targeted the ioctl handlers belonging to network interfaces lo0 and enc0.

One ioctl handler was overwritten to hijack kernel control flow.

The second ioctl handler was utilized to restore the overwritten pointer.

### Industry impact

Calif published these offensive findings alongside ongoing defensive work with open-source communities.

The research highlighted defensive techniques adopted in NetBSD and FreeBSD that OpenBSD could evaluate.

FreeBSD and NetBSD implement safe-unlinking inside their sys/queue.h implementations.

Safe-unlinking verifies doubly linked list invariants before completing unlink memory writes.

If invariant checks fail, the system invokes an abort or panic to block corruption.

Calif engaged FreeBSD regarding compiler-level array bounds sanitization mitigations.

Calif suggested enabling array bounds sanitizers in release builds for exploit prevention.

Calif privately reported 21 issues to FreeBSD that bounds sanitizers would detect.

Some of those 21 reported FreeBSD flaws carried local privilege escalation security impact.

### What to watch next

Calif proposed randomizing the self-referential PTE map allocation address at boot.

Randomization can use a boot-time byte from .openbsd.randomdata to select a PML4 slot.

The slot selection uses the formula 320 plus the random byte masked with 127.

This change turns PTE_BASE into a runtime expression spanning 0xffffa00000000000 through 0xffffdf8000000000.

The resulting base addresses would be separated by 512-GiB intervals.

Alternative PTE defenses include marking PTEs read-only and modifying CR0.WP during updates.

The kernel allocator could adopt boot-time base address randomization without performance penalties.

Runtime allocation order randomization could also be introduced, though it incurs some overhead.

Future compiler features like Alloc Tokens could isolate pointer allocations from non-pointer allocations.

Alloc Tokens would hinder use-after-free exploitation between different allocation categories.

Array bounds sanitizers could systematically eliminate out-of-bounds accesses on fixed-size arrays.

Background: OpenBSD has championed W^X, ASLR, sandboxing, privilege separation, and source auditing.

Background: It is not yet known which proposed structural mitigations OpenBSD will officially adopt.

## 5. BAE Systems cyberattack disrupts US federal court operations

### Overview

A cyberattack targeting BAE Systems has disrupted the US federal bankruptcy notice system.

The Administrative Office of the US Courts announced the disruption in a Thursday press release.

The security incident halted both the production and the delivery of bankruptcy notices.

BAE Systems operates the Bankruptcy Noticing Center systems on behalf of the federal Judiciary.

Court administrators confirmed that access to multiple critical portals remains offline.

Both BAE Systems and court officials are coordinating closely to investigate the attack.

Efforts to restore standard bankruptcy court operations are currently ongoing.

### What happened

The Administrative Office of the US Courts publicly disclosed the cyberattack on Thursday.

The incident directly hit systems operated by major contractor BAE Systems.

All access to the BNC systems and related websites became completely unavailable.

Impacted websites include the primary domain bnc.uscourts.gov.

The online platform bankruptcynotices.uscourts.gov was also taken offline.

Users are unable to access the court noticing portal at notices.uscourts.gov.

The National Creditor Registration Service was shut down as a result of the incident.

AOUSC established direct communication with all federal bankruptcy courts affected by the disruption.

A BAE Systems spokesperson confirmed the company is aware of the security incident.

BAE Systems stated that the intrusion was isolated specifically to the BNC system.

The contractor stated that it took immediate steps to address the security event.

BAE Systems confirmed it is coordinating closely with AOUSC on the response.
