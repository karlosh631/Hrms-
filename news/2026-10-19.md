## 1. Linux KVM guest-host escape rated critical, may represent a new way to attack penguin-powered networking

### Overview

Security researcher Paulos Yibelo has identified a critical vulnerability in Linux KVM.
The security flaw has been assigned the tracking identifier CVE-2026-99999.
Yibelo has formally named the newly discovered vulnerability PwnEscape.
The vulnerability carries a critical severity rating of 9.3.
PwnEscape allows an attacker in a guest virtual machine to escape to the host.
The exploit can be carried out by sending a guest a few malformed IPv4 packets.
Linux KVM serves as the core hypervisor powering most hyperscale clouds.
Experts warn the vulnerability may represent an entirely new way to attack Linux networking.

### What happened

Paulos Yibelo disclosed his discovery of the KVM guest-host escape flaw in early October.
The vulnerability was subsequently registered in public databases as CVE-2026-99999.
Red Hat engineer Michael S. Tsirkin documented the issue in the Linux kernel stable tree.
Tsirkin reported that packets with bad checksum metadata cause corruption in the IPv4 stack.
Specifically, the function skb_checksum_help can corrupt the network header.
Tsirkin warned that this header corruption causes a significant amount of mischief.
Kernel developers have since authored an upstream fix within the Linux kernel.
The patch is currently filtering into major distributions, including Debian, RHEL, and Ubuntu.
Virtualization platforms relying on KVM, such as Nutanix and Proxmox, are also receiving updates.

### Why it matters

Virtualization relies on splitting server hardware into isolated guest virtual machines.
Guest virtual machines share host server resources without visibility into other guests or the host.
Public and private cloud infrastructures depend entirely on impervious guest-host isolation.
Violating this isolation boundary allows attackers to potentially access all virtual machines on a host.
