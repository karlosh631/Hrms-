## 2. DeepSeek deep-sixed at all US federal civilian agencies

### Overview

The US Department of Homeland Security has banned DeepSeek across federal civilian agencies.
Agencies must remove all existing technology implementations tied to the Chinese artificial intelligence lab.
The order applies to DeepSeek products and third-party tools developed using them.
Cybersecurity experts argue the directive is excessively broad and practically unenforceable.
The mandate could increase agency software costs by limiting access to low-cost models.

### What happened

The Department of Homeland Security issued its directive to civilian agencies on Monday.
Agencies are instructed to ditch all DeepSeek and DeepSeek-affiliate products immediately.
The mandate explicitly extends to third-party services developed using DeepSeek implementations.
A Department of Homeland Security spokesperson did not immediately respond to inquiries.
US scrutiny intensified following the release of the DeepSeek-R1 model in early 2025.

Their No DeepSeek on Government Devices Act failed to advance out of committee.

## 3. Amazon is taking its biggest shot at Nvidia yet with new TorchNeuron dev tool

### Overview

Amazon Web Services has launched a developer tool named TorchNeuron.
The tool helps startups transition AI workloads to Amazon's Trainium chips.
This move represents Amazon's most aggressive challenge to Nvidia to date.
Nvidia has long enjoyed a software advantage in artificial intelligence.
TorchNeuron is built to integrate directly with the PyTorch framework.
Developers can migrate their applications with minimal configuration effort.
Amazon also wants to uncouple PyTorch from specific proprietary hardware.
The strategy targets both hardware costs and software developer choice.

### What happened

AWS announced the release of TorchNeuron on Monday.
The tool allows AI applications to run on Amazon's Trainium silicon.
Developers can port PyTorch applications by changing one configuration line.
Amazon confirmed that no full code rewrite is required for migration.
TorchNeuron is adapted directly from the standard PyTorch framework.
Engineers familiar with PyTorch can easily navigate the new tool.
Amazon also announced plans to contribute code upstream to PyTorch.
These upstream contributions aim to remove vendor-specific chip ties.
The company published details about the initiative in an official blog post.

### Why it matters

Nvidia is currently the default hardware provider for artificial intelligence apps.
Nvidia achieved this through years of engineering its CUDA software platform.
CUDA ensures that Nvidia hardware supports PyTorch applications seamlessly.
This deep integration effectively embedded Nvidia hardware by default.
Amazon notes that roughly 85 percent of AI applications utilize PyTorch.
Colin Brace of AWS stated that developer lock-in must be removed.
Breaking this lock-in could have massive ramifications for Nvidia's business.
Lowering software barriers provides startups with genuine hardware alternatives.

### Technical details

PyTorch is a free, open-source machine learning toolkit.
Developers use PyTorch to build, train, and run AI models.
Facebook originally created PyTorch for artificial intelligence development.
The framework became part of the Linux Foundation in 2022.
The Linux Foundation actively maintains PyTorch as an open project.
PyTorch already supports switching to AMD GPUs via configuration changes.
Apple silicon chips can also run PyTorch using simple configuration changes.
Amazon's Trainium silicon performs both model training and model inference.
Training represents the phase where an AI model learns from data.
Inference represents putting the finished model to work answering queries.
Combining training and inference on one platform improves overall workload economics.
AI voice provider Deepgram moved its workloads to Trainium via PyTorch.
Deepgram is an AI voice application company that competes with ElevenLabs.
Deepgram processes 70 percent more audio per dollar at production accuracy.

AWS argues that startups benefit from having an entire cloud ecosystem.

## 5. F5 releases out-of-band patches for critical NGINX vulnerabilities

### Overview

F5 has published out-of-band security fixes for critical NGINX web server flaws.
The security release addresses three critical-severity flaws in the software.
Unprivileged remote attackers can exploit these weaknesses to execute arbitrary code.
Successful exploitation can also result in denial-of-service conditions.
Systems with specific non-default configurations are at risk.
Remote threat actors do not require privileges to trigger these security flaws.

### What happened

F5 released patches outside its regular update cycle for NGINX software.
Two critical vulnerabilities reside inside the ngx_http_v3_module component.
These HTTP/3 vulnerabilities are tracked as CVE-2026-15176 and CVE-2026-97205.
A third critical flaw was identified in the NGINX map directive.
The map directive vulnerability is tracked as CVE-2026-93479.
F5 deployed security fixes across multiple enterprise and open-source NGINX products.
Fixed software includes standard NGINX Open Source deployments.
The commercial NGINX Plus product line received security patches.
F5 also patched the NGINX Ingress Controller software.
Security updates were released for NGINX Gateway Fabric.
NGINX Instance Manager is also among the patched products.

### Why it matters

Unauthenticated attackers can target exposed NGINX worker processes remotely.
Exploitation leads to heap-based buffer overflows or use-after-free states.
Memory corruption can cause worker processes to crash or restart immediately.
Attackers can execute arbitrary code on systems where ASLR is disabled.
Arbitrary code execution can also occur if the attacker bypasses ASLR.
F5 products are historically high-priority targets for malicious threat groups.
Threat actors previously exploited F5 flaws to breach corporate computer networks.
Intruders have mapped internal servers and hijacked vulnerable devices.
Attackers have also deployed destructive data-wiping malware through F5 vulnerabilities.
Previous F5 security incidents involved the theft of sensitive enterprise files.

### Technical details

Exploitation requires the presence of non-default NGINX server configurations.
Attackers without privileges can exploit all three critical vulnerabilities remotely.
