## 1. AWS distills its cloud into a local emulator that runs on your PC

### Overview
AWS has released a local tool called "AWS Emulator" to run cloud APIs on personal computers.
The emulator acts as a local program that serves an AWS API endpoint directly on a laptop.
Developers can test their applications locally without making network calls to the AWS cloud.
Because API tests never touch the live AWS cloud, using the emulator tool is entirely free.
The utility brings micro-computing and hyperscale cloud development closer together for software engineers.
It supports testing on developer machines, dedicated development servers, and continuous integration pipelines.
The emulator does not replicate the full AWS cloud infrastructure.
Instead, it focuses on offering local endpoints for AWS application programming interfaces.

### What happened
AWS announced the release of its new tool through a dedicated GitHub repository.
The software is prosaically named "AWS Emulator."
AWS senior specialist solutions architect Daniel Abib detailed the operation of the new tool.
The tool allows developers to verify software without risking live deployment costs on AWS.
The Register noted that the AWS API models GitHub repository lists over 1,300 API models.
AWS also provided an `aws-emulator` skill allowing AI coding agents to drive tests.

### Technical details
AWS engineered the local emulator using the Rust programming language.
Abib explained that Rust ensures the tool remains light on CPU and memory usage.
The emulator supports services that have models in the official GitHub API models repository.
The tool does not replicate all features of the live Amazon cloud environment.
It does not evaluate Identity and Access Management policies in the way AWS does.
Each emulator instance functions strictly as a single isolated cloud account.
There is no support for cross-account or cross-Region behavior in the local program.
AWS publishes fidelity scores detailing how closely the emulator matches live cloud services.
Full fidelity ensures valid API calls produce identical results and invalid calls produce identical errors.
Linux users can install the emulator as an RPM or Debian software package.
Mac and PC users must run Docker along with an image of the emulator.
Starting the emulator generates local credentials, a config file, and a security certificate.
These files are automatically written to the directory path `~/.aws/emulator/9297/`.
Developers configure environment variables so the AWS SDK targets their local machine.
Existing CLI scripts and application code remain completely unchanged during local testing.
The `aws-emulator` agent skill checks project dependencies against official fidelity scores.
The skill informs developers which parts of a project will match AWS behavior precisely.

## 2. Critical RCE Vulnerability in Apache HTTP Server

### Overview

Security researchers have disclosed a critical remote code execution vulnerability in Apache HTTP Server.
The security vulnerability is officially designated as CVE-2026-119618.
The flaw impacts Apache HTTP Server deployments utilizing the HTTP/2 module.
Specifically, the issue involves the mod_http2 module.
According to cloud security data, 64% of cloud environments contain vulnerable resources.
Immediate patching is strongly advised for system administrators.

A critical synchronization vulnerability has been identified within the web server code.
The flaw stems from a race condition occurring during concurrent execution.
An unauthenticated remote attacker could exploit this vulnerability to corrupt heap memory.
Successful exploitation leads to arbitrary code execution on the target server.
There are currently no reports of active exploitation in the wild.
No publicly available exploit code exists as of the disclosure date.

### What happened

The critical vulnerability was independently discovered by two separate research teams.
Anthropic discovered the race condition during security research.
Google Cloud’s Vulnerability Research Team also independently identified the issue.
Both teams discovered improper synchronization within the HTTP/2 implementation.

The flaw specifically exists inside the assign_headers() function of mod_http2.
Researchers alerted Apache to the flaw in the HTTP/2 module.
Apache has issued version updates to eliminate the vulnerability.
Security firm Wiz released metrics detailing potential enterprise exposure.

### Why it matters

CVE-2026-119618 represents a high-severity risk to web hosting infrastructure.
An attacker does not require authentication to trigger the vulnerability.
Exploitation allows attackers to execute arbitrary commands on the target host.
The commands run with the full privileges of the web server process.

In modern cloud environments, compromised Apache instances pose extended risks.
A compromised server hosting containerized workloads can serve as an initial access point.
Attackers can use a breached web server to perform lateral movement.
Lateral movement attempts can target adjacent microservices within the cloud network.
Threat actors can also attempt to access sensitive cloud metadata endpoints.

### Technical details

The flaw is rooted in an execution race condition within assign_headers().
This function fails to maintain proper synchronization during concurrent thread execution.
When concurrent threads share resources improperly, heap memory becomes corrupted.
This heap corruption enables unauthorized threat actors to execute remote code.

The vulnerability affects deployments using HTTP/2 capabilities on Apache HTTP Server.
Deployments running affected versions require mitigation or software updates.
Apache HTTP Server versions prior to version 2.4.71 are affected by this flaw.
Standalone mod_h2 module builds from GitHub version 2.0.42 and older are also vulnerable.

* Background: Apache HTTP Server is a widely used open-source web server platform.
* Background: The mod_http2 component enables HTTP/2 protocol support for client connections.
* Background: Concurrent execution race conditions occur when thread synchronization fails during resource access.
* Background: Heap memory corruption can allow malicious code to overwrite memory pointers.
* Background: It is not yet publicly known whether real-world threat actors are attempting scanning activity.
* Background: The total exact number of vulnerable standalone GitHub module deployments remains unknown.

### Industry impact

Cloud security company Wiz analyzed scanning data across cloud environments.
Data shows that 64% of cloud environments contain resources vulnerable to CVE-2026-119618.
Furthermore, 51% of cloud environments have publicly exposed vulnerable instances.
This demonstrates widespread exposure across external cloud attack surfaces.

The collected scanning metrics do not account for individual server configurations.
Some exposed instances might not have the mod_http2 module active.
Despite configuration nuances, the high percentage indicates broad potential risk.
Organizations must review their public-facing web infrastructure immediately.

### What to watch next

Security operations and engineering teams must begin immediate remediation steps.
Administrators should upgrade Apache HTTP Server to version 2.4.71 or later.
Upgrading to version 2.4.71 resolves the synchronization flaw in assign_headers().
Standalone mod_h2 module builds from GitHub must be updated to versions newer than 2.0.42.

If immediate patching is impossible due to operational constraints, workarounds exist.
Administrators can temporarily disable HTTP/2 support to block the attack vector.
Disabling HTTP/2 involves editing server configuration files such as httpd.conf.
Removing h2 and h2c protocol references restricts protocol options strictly to HTTP/1.1.

Wiz customers can search for vulnerable instances using pre-built queries.
The Wiz Threat Center provides dedicated advisories for tracking this CVE.
Security teams will watch for any emerging public exploit code.
Defenders will monitor network traffic for exploitation attempts targeting HTTP/2 endpoints.
Organizations will continue tracking patch verification across all cloud workloads.
