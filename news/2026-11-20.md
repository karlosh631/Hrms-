## 1. PostgreSQL 19

### Overview

- PostgreSQL 19 has been detailed with numerous performance upgrades and system enhancements.
- The release introduces new commands, extended statistical tools, and altered security defaults.
- Database administrators can utilize a built-in REPACK command for online table reorganization.
- JIT compilation is now disabled by default due to unreliable optimizer cost calculations.
- Upgrading to PostgreSQL 19 requires a dump and restore, pg_upgrade, or logical replication.
- The update introduces key performance gains in join processing and background worker management.
- Storage compression defaults have transitioned to lz4 for improved efficiency.
- Standby databases now support read-your-writes consistency using a new WAIT command.
- Security has been updated by removing unfixably insecure RADIUS over UDP support.
- System monitoring expands with several new statistical views and process metrics.

### What happened

- PostgreSQL 19 introduces a REPACK command to reclaim disk space and reorganize tables.
- Using REPACK CONCURRENTLY allows repacking without blocking active table reads and writes.
- Two new extensions, pg_plan_advice and pg_stash_advice, provide control over query planner decisions.
- Logical replication can now be enabled without restarting the server when wal_level is set to replica.
- Autovacuum operations now support parallel execution across table indexes.
- A new scoring system has been added to prioritize autovacuum tasks across databases.
- Automatic scaling has been added for the number of I/O worker processes.
- The io_workers server variable was removed and replaced by four new background worker control variables.
- Standard_conforming_strings is now permanently forced to be enabled on the database server.
- Insecure RADIUS over UDP authentication support has been completely removed from PostgreSQL.
- Database, role, and tablespace names can no longer contain carriage returns or line feeds.
- Default index opclasses for inet and cidr data types shifted from btree_gist to GiST.
- The default password expiration warning period was set to seven days via a new server variable.
- MD5 password authentication now issues a warning following successful login attempts.
- The obsolete MULE_INTERNAL text encoding has been completely removed from PostgreSQL 19.

### Why it matters

- Automatic I/O worker scaling improves overall database scalability under heavy workloads.
- Disabling JIT by default prevents unexpected performance degradation on standard queries.
- Sites executing large analytical queries must now manually enable JIT compilation when beneficial.
- Read-your-writes consistency via the WAIT command ensures standby nodes serve up-to-date query results.
- The shift to lz4 as the default TOAST compression algorithm improves data storage efficiency.
- Shared cost-based vacuum delays ensure parallel autovacuum workers stay strictly within configured limits.
- Preventing control characters in object names eliminates specific security vulnerabilities during operations.
- Eliminating broken btree_gist index classes prevents queries from returning incomplete or missing rows.
- Forcing standard_conforming_strings prevents string literal interpretation errors across client applications.
- System administrators receive clearer operational visibility through expanded system statistics views.
- Simplified constant folding in the optimizer speeds up boolean logic and conditional query execution.
- Quicker foreign-key constraint checks reduce overall latency during data operations.

### Technical details

- The server now features io_min_workers, io_max_workers, io_worker_idle_timeout, and io_worker_launch_interval variables.
- SIMD CPU instructions now accelerate COPY FROM operations processing text and CSV data formats.
- NOTIFY signals now target only backends listening for specific notification events.
- Query table scans can now mark pages as all-visible directly inside the visibility map.
- TID Range Scans can now be parallelized across multiple process workers.
- Aggregate processing can occur prior to join execution to reduce processed row counts.
- Optimizer enhancements convert eligible NOT IN and LEFT JOIN queries into ANTI JOINs.
- Extended statistics are now supported on virtual generated columns.
