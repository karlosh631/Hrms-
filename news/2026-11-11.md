## 2. VMware floats new standard to make sure apps don’t break in hybrid K8s environments

### Overview

Welcome to today's IT news digest for November 11, 2026.

VMware has taken the lead in establishing a new standard for hybrid Kubernetes environments.

The effort is designed to ensure that applications do not break when deployed across hybrid clouds.

---

### What happened

VMware has spearheaded the creation of the Workload Conformance Working Group within the Kubernetes community.

The working group aims to establish a shared standard for how workloads run on Kubernetes.

The group's web page points out that Certified Kubernetes tests the cluster itself.

It also notes that Kubernetes AI Conformance tests whether a cluster can run AI and machine learning workloads.

However, nothing comparable currently exists for the workloads themselves.

Cluster operators still check each application by hand before routine maintenance or a Kubernetes upgrade.

Every cluster operator ends up repeating the exact same assessment.

Application maintainers also get the same questions from each environment they support.

The group proposes a common specification with repeatable tests to give both groups a shared baseline.

Prashanth Shenoy, VP of product marketing in Broadcom's VMware Cloud Foundation division, spoke to The Register about the initiative.

Shenoy noted that applications packaged to run in public clouds do not always run well in hybrid clouds.

In addition to this working group, VMware announced another contribution to Kubernetes this week.

The company is moving its VM API to the Cloud Native Computing Foundation (CNCF) Sandbox.

---

### Why it matters

The lack of workload standardization is challenging for VMware and other vendors of hybrid clouds like Nutanix and Red Hat.

These vendors all sell tools to create and run a stack that users can deploy to both on-prem infrastructure and public clouds.

VMware believes it will find strong support for ensuring cloud-native apps run predictably and efficiently in any Kubernetes environment.

Shenoy thinks application vendors will likely support the effort because they want to package their wares once and have them run anywhere.

The CNCF's interest shows that the VM API move is not merely a vanity project for VMware.

While developers generally prefer writing for containers, operations personnel often decide to run those abstractions within lightweight VMs.

The two abstractions will therefore coexist for years to come for new applications.

They will also coexist as organizations run new containerized apps alongside legacy VMs in an infrastructure-as-code world.

---

### Technical details

The effort to create the workload standard is currently in its very early days.

The announcement of the working group's formation states that the first step is deciding which workloads and behaviors the specification covers.

The scope of the specification includes security, resilience during disruptions, and resource use.

It also covers networking, storage, API usage, and observability.

The group has not yet agreed on specific requirements or on how to test them.

However, one rule is already set: every requirement needs an objective test that a test binary can run.

This rule ensures that nothing subjective goes into the specification.

Meanwhile, the CNCF already maintains KubeVirt, a tool that allows users to create and manage VMs inside a Kubernetes cluster.

VMware's VM API lets Kubernetes users create VMs that run under other hypervisors, including VMware’s own ESXi.

---

### Industry impact

Advocates for cloud-native software have long argued that their approach makes applications portable across different Kubernetes environments.

VMware argues that this portability is not actually happening across hybrid clouds.

By taking the lead in the Kubernetes community, VMware is addressing a persistent operational bottleneck.

The VM API represents another option to make life easier for operations and development teams alike.

VMware previously integrated Kubernetes into vSphere with Kubernetes, which was introduced as part of vSphere 7 in 2020.

Past efforts by Virtzilla to package and sell the container tech acquired from Pivotal Software did not catch on.

VMware is now trying a different approach to making virtual machines a first-class citizen of Kubernetes.

The VM API will likely be a welcome addition to Kubernetes for automated deployments.

---

### What to watch next

The newly formed Workload Conformance Working Group has yet to finalize its specific requirements.

The group still needs to determine how to test the behaviors included in its scope.

Organizations will monitor whether application vendors broadly adopt the proposed common specification.

Developers and operators will watch how the VM API integrates within CNCF environments over the coming years.

Background: VMware has a long history with container technology following its acquisition of Pivotal Software.

Background: The CNCF is the home of Kubernetes and KubeVirt.

Background: It is not yet known how long the working group will take to finalize its complete conformance specification.

## 4. Hackers exploit trusted AWS access to breach multiple cloud environments

### Overview

Today is November 11, 2026, bringing critical cloud security news.

A sophisticated threat actor recently exploited trusted AWS access.

Multiple cloud environments suffered breaches in this campaign.

Compromised IAM credentials belonged to Qubole's AWS account.


### What happened

The malicious campaign ran between October 14 and 26.

Tens of companies were affected by the security breach.

These companies had AWS environments with specific IAM roles configured.

Those roles trusted an AWS account associated with Qubole.

Qubole is an enterprise cloud data processing and analytics platform.

Data security company Sentra initially spotted suspicious activity.

Sentra shared this information with cloud security company Wiz.

Researchers at Wiz began a deep investigation of the attack.

Cybersecurity company Mandiant also joined the investigative effort.

BleepingComputer reached out to Qubole for comment.

No public announcement from Qubole has been found yet.

An AWS spokesperson clarified that AWS services were not compromised.

The spokesperson noted that AWS services operated entirely as designed.


### Why it matters

Attackers leveraged trusted third-party access to bypass security boundaries.

The breach demonstrates risks in cross-account IAM role configurations.

Victims suffered massive data exfiltration across numerous environments.

One single customer alone lost millions of stolen files.

The attacker moved rapidly through compromised cloud environments.

Secret collection occurred at a staggering rate of 100 passwords in seven minutes.


### Technical details

The attacker compromised two specific Qubole IAM users.

They assumed otherwise unused roles in multiple customer AWS accounts.

These accounts were previously configured to trust Qubole's account.

External providers use AWS's STS AssumeRole API for temporary credentials.
