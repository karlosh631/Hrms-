## 2. Oracle reveals fix-this-ASAP-grade Java4Shell bug that allows attacks on many third-party apps

### Overview

Today is November 18, 2026.

The United States Cybersecurity and Infrastructure Security Agency is urging Java users to patch immediately.

Oracle has revealed a fix-this-ASAP-grade Java bug.

The vulnerability is tracked as CVE-2026-114938.

Attackers can use the flaw to crash the Java virtual machine.

The issue also allows unauthenticated remote code execution.

Calif.io discovered the critical software flaw.


### What happened

Oracle revealed the flaw in its monthly patch dump for November.

The November dump offers 655 patches affecting 62 products.

Sixty-two of these patches are rated critical.

Oracle did not single out CVE-2026-114938 as worthy of special attention.

CISA nonetheless issued an urgent warning to Java users.

Vulnerability research outfit Calif.io used X to claim news leaked before public disclosure.

News leaked before Oracle released its fixes.

Calif had already tested the flaw by the time of the leak.


### Why it matters

Calif named the vulnerability "Java4Shell".

The firm found multiple major applications are susceptible to remote code execution.

Affected applications include Keycloak, Atlassian’s Jira, and Confluence.

Other vulnerable tools include Jenkins, Apache Kafka Broker, and Elasticsearch.

Calif applied the CVSS 4.0 rating scheme to the bug.

The firm assigned Java4Shell a critical score of 9.2 out of 10.

SentinelOne noted the flaw sits in the Java standard library.

Exploit traffic is therefore specific to each application.

Attackers can reach the vulnerable code path prior to authentication in default configurations.


### Technical details

Calif says the flaw is a memory-corruption vulnerability.

The issue resides in OpenJDK's Base64 decoder.

Base64 is used to represent binary data as text.

It appears in authentication protocols, file uploads, and network messages.

OpenJDK uses specialized x86-64 CPU instructions to decode Base64 faster.

A bug exists in that optimized machine-level code.

Malformed input lets the bug overwrite neighboring memory.

Careful exploitation can reveal sensitive memory or lead to remote code execution.

The corruption triggers with just 64 A characters followed by a single equals sign.

Cisco’s Talos security team says the flaw affects OpenJDK Java versions 17.0.6 and later.

It impacts systems running on x86-64 CPUs with AVX-512 VBMI support enabled.

Calif used AI-powered flaw finders that burned through just $200 in tokens to find it.


### Industry impact

Cisco urged the adoption of the fixed versions of Java Oracle posted on Tuesday.

Admins can mitigate the flaw on x86-64 machines by starting the JVM with AVX-512 disabled.

Akamai Chief Information Security Architect Jan Schaumann expressed discomfort with Calif’s publicity-maxxing priorities.

Schaumann noted Calif's announcement referenced their previous PHP2Shell discovery.

Tenable Security counts 249 of Oracle's patches as targeting high severity bugs.

Oracle's Hyperion enterprise performance management accounts alone for 267 of the patched bugs.

Oracle also reported six separate 10.10-rated flaws.


### What to watch next

Talos has not observed in-the-wild exploitation of Java4Shell yet.

Talos anticipates probing attempts may pick up soon after public disclosure.

Java4Shell deserves a high place on patch priority lists alongside other Oracle flaws.
