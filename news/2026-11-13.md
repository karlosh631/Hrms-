## 2. Edge0-145B: Frontier AI Capabilities on Your Own Computer

### Overview

Edge0 has open-sourced the Edge0-145B and Edge0-120B models.

They released these models alongside a unified inference framework and deployment tools.

Edge0-145B is the world's first open-source on-device AI model with 145 billion parameters.

It brings coding, reasoning, and agent capabilities that rival frontier cloud models directly to personal computers.

The full stack is being released so developers can reproduce results, evaluate models, fine-tune them, and integrate products.

### What happened

Developers can obtain model weights, explore the inference framework, or try the Edge0 App.

The release addresses historical constraints of on-device AI in four distinct ways.

Edge0-145B makes a 145-billion-parameter model usable on a personal laptop.

Earlier phone releases like Edge0-35B reported peak memory usage below 2.5GB.

On an iPhone 18 Pro Max, Edge0-35B delivers over 37 tokens per second.

In contrast, Edge0-145B reports 80+ tokens per second and 28GB peak memory on a laptop.

These measurements apply to different models and distinct hardware environments.

Edge0-145B combines a 72.8 mean score across six benchmarks with a measured peak memory of 29GB.

This puts Edge0-145B at about 40 percent of estimated baseline memory compared to Qwen3.8-Flash-Next.

The model enables local use on a 48GB laptop.

### Why it matters

On-device AI has long forced a tradeoff between model capability and available hardware.

Larger models demand more memory, bandwidth, and power while smaller models struggle with complex work.

Moving work to the cloud adds model-provider fees and data-handling constraints.

It also introduces an undesirable dependence on network connectivity.

Privacy alone could not close the capability gap between cloud and local models.

Local inference eliminates corresponding cloud-model token and API charges entirely.

Code and data can stay securely on the user's computer.

Core model capabilities continue to work completely offline.

### Technical details

The model and inference engine were designed together to reduce memory and data movement.

The design spans architecture, training, loading, and scheduling.

Large matrices are shared across sparse experts in the model architecture.

Each group of 64 experts shares two large matrices.

Each expert retains a small set of parameters capturing its differences.

Only about 10 billion of the 145B total parameters participate in computation on each inference step.

The model was built for local execution from day one during training.

Loading pipelines GPU memory, system memory, and SSD access together.

Frequently used hot experts remain in GPU memory.

An expert library of roughly 40GB sits in system memory.

Approximately 48GB of vocabulary data resides on the SSD and is read on demand.

Scheduling uses the CPU and GPU together in parallel.

The GPU computes cached experts while the CPU handles remaining work.

Speculative decoding verifies multiple candidate tokens at once.

### Industry impact

Edge0-145B is competitive with specific frontier cloud models across coding, reasoning, knowledge, and instruction following.

Its score of 86.52 on Terminal-Bench 2.1 exceeds Qwen3.8-Flash-Next, DeepSeek-V4-Flash-0731, and Claude.

On AA-LCR, Edge0-145B scores 79.3 compared to Claude's 78.0.

The largest gains over Qwen3.8-27B are 18.5 percent on Terminal-Bench and 53.1 percent on DeepSWE.

Edge0-145B produced a video explainer about how Roadster could fly within an hour.

It built a 3D scene of Manhattan inside Blender from text and reference images.

The model created a playable fantasy RPG medieval capital and rendered a 20-second fly-through.

It wrote a program for a real drone from a single instruction.

It took a PCB design from component placement through to an assembly visualization in KiCad and Unreal Engine 5.

### What to watch next

Developers are encouraged to get model weights and explore the inference framework.

The complete evaluation setup, hardware environment, and reproduction instructions are being released with the technical report.

Future adoption will show how local 100B+ parameter models change developer workflows.

Users will test whether trade-secret protection and data-handling requirements drive more local hardware investments.

The industry will observe if other labs attempt to match this sparse expert sharing approach.

## 3. Hackers compromise 4,800 GitHub accounts to steal cloud credentials

### Overview
Tens of thousands of GitHub repositories were targeted in a campaign dubbed ‘wfx-loot’.
The campaign began around 12:45 UTC on November 10.
Threat actors used malicious workflows to steal GitHub Actions secrets and cloud credentials.
Researchers at application security company Aikido uncovered the ongoing operation.
The attack highlights critical supply chain and credential security risks.

### What happened
Attackers leveraged stolen GitHub credentials from 4,837 compromised accounts.
They probed 61,764 repositories for write access permissions.
Compromised accounts opened pull requests titled ‘docs: dependency audit notes’.
The pull requests were cleverly disguised as legitimate dependency audit notes.
About 92% of those pull requests remained open according to Aikido.
This high percentage suggests legitimate repository owners failed to notice the activity.
Although not all repositories ran the payload, secrets were stolen from at least 1,835 targets.
Some compromised accounts belonged to major and governmental organizations.
Victims included Fortune 100 organizations and the US General Services Administration.
Other affected entities included the French government, Nextcloud, and WebdriverIO.

### Why it matters
About 50 of the compromised accounts possessed publishing rights on other software ecosystems.
These included open-source software ecosystems and package indexes.
Targeted package ecosystems included npm, PyPI, Go, crates, and Packagist.
Automated publishing carried the payload into specific live packages.
Affected packages included Packagist’s digitalelvis/neuronai-studio 3.14.3.
Two versions of the Go module github.com/onuragtas/docker-env were also affected (v1.0.278 and v1.0.280).
Researchers believe the primary objective was to steal CI secrets.
Package releases functioned merely as a byproduct of automated publishing.
Certain overlaps were found with the previous 2025 GhostAction campaign.

### Technical details
The threat actor delivered a 1,500-line credential-stealing shell script.
The script was delivered by modifying an existing GitHub Actions workflow.
Alternatively, it was added via a new workflow on a short-lived branch or an npm install hook.
The script supported cloud privilege escalation using GitHub OIDC tokens.
It exchanged tokens for temporary AWS, Azure, and GCP cloud sessions.
In AWS, it chained into additional IAM roles present in the repository.
This allowed the creation of long-lived credentials for IAM users.
In GCP, it used collected service-account credentials to impersonate identities.
Capabilities included establishing persistent access by modifying trust policies.
Collected data was compressed into tarballs.
It was exfiltrated via HTTP POST to one of two attacker-controlled endpoints.
The attacker quickly reverted changes and deleted workflow runs and logs.
This cleanup phase was completed in under a minute.

### Industry impact
The campaign exposed vulnerabilities in how repositories handle write permissions.
Open-source software supply chains faced direct contamination risks.
Multiple major governmental and corporate entities had accounts compromised.
The incident emphasizes the risks of automated publishing pipelines.
Security researchers continue to monitor related threat actor movements.

### What to watch next
Repository owners are advised to look for specific indicators of compromise.
Check for the presence of the ‘wfx-docs’ branch on repositories.
Look out for the probe pull request and gaps in workflow run numbers.
Where payload execution is confirmed, all associated secrets must be handled safely.
All secrets and cloud roles available to affected workflows should be considered compromised.
All affected secrets and roles should be rotated immediately.

Background:
GitHub Actions allows developers to automate software development lifecycles.
Secret management within CI/CD pipelines remains a major challenge for security teams.
It is not yet known who specifically orchestrated the wfx-loot campaign.
The total financial damage from compromised cloud sessions is still undetermined.

## 4. Apache HTTP Server patches critical HTTP/2 remote code execution flaw

### Overview

Today is November 13, 2026.

An important security update has been released by the Apache Software Foundation.

A critical vulnerability affects the HTTP/2 module of the Apache HTTP Server.

The issue could allow an unauthenticated attacker to achieve remote code execution.

The vulnerability is now officially tracked under the identifier CVE-2026-119618.

Anthropic’s OSS Scanner and Google Cloud’s Vulnerability Research teams discovered the flaw.

The Apache HTTP Server is a widely used, free, and open-source software.

It handles requests from web browsers and serves pages, images, and other website content.

The software is estimated to back roughly one out of every five websites.


### What happened

The Apache Software Foundation has issued patches to address the critical flaw.

However, a significant number of servers remain vulnerable and are reachable over the public internet.

Security researchers at watchTowr have confirmed the condition.

watchTowr recommends that technicians patch immediately or drop HTTP/2 until patching is complete.

Wiz assesses the overall severity of the vulnerability to be critical.

No official CVSS score is currently available for CVE-2026-119618.

The latest version of the server software also addresses two additional flaws.

These include CVE-2026-106023, a null pointer dereference in 'mod_md'.

They also include CVE-2026-109163, a low-severity data overwrite flaw in 'mod_vhost_alias'.


### Why it matters

An attacker who successfully exploits the vulnerability can run arbitrary code.

This code would run with the privileges of the web server process.

Unauthorized threat actors could leverage the heap corruption to execute commands.

Telemetry data from cloud security company Wiz indicates widespread exposure.

Wiz data shows that 64% of cloud environments contain vulnerable resources.

Roughly half of those vulnerable cloud environments have publicly exposed instances.

These numbers do not account for specific server configurations.

The flaw requires HTTP/2 to be enabled, though the default setting is off.


### Technical details

The vulnerability resides specifically in the `mod_http2` module of the Apache HTTP Server.
